# c-sharp-api-template

.NET 10 Web API template, built to run in Docker on Hetzner Cloud.
Architecture and decisions: [`docs/ARCHITECTURE.md`](docs/ARCHITECTURE.md).

## What's inside

| Path | Purpose |
|---|---|
| `src/Template.Api` | HTTP edge: Minimal API endpoints, ProblemDetails, health checks, OpenAPI + Swagger UI, Dockerfile |
| `src/Template.Application` | Use cases (handlers, validators, `Result<T>`). No HTTP or Npgsql types |
| `src/Template.Domain` | Entities and invariants. No framework dependencies |
| `src/Template.Infrastructure` | EF Core + PostgreSQL, migrations, DI wiring |
| `tests/*` | Unit, architecture (layer rules) and integration tests (real Postgres via Testcontainers) |
| `deploy/compose` | Production Compose stack (Caddy, API, migrator, Postgres) + local override |

`Orders` is a sample feature showing the full path from endpoint to database. Replace it, and rename `Template` to your product name.

## Prerequisites

- .NET SDK 10.0.100+ (pinned in `global.json`)
- Docker (for integration tests and the Compose stack)

## Run locally

Option A: API on the host, Postgres in Docker

```bash
docker run -d --name template-pg -e POSTGRES_PASSWORD=postgres -e POSTGRES_DB=template -p 5432:5432 postgres:18
dotnet tool restore
dotnet ef database update --project src/Template.Infrastructure --startup-project src/Template.Api
dotnet run --project src/Template.Api
```

Option B: everything in Docker

```bash
cd deploy/compose
cp .env.example .env
docker compose up -d --build postgres api
docker compose run --rm --build migrate
```

Swagger UI: <http://localhost:5080/swagger> · OpenAPI document: <http://localhost:5080/openapi/v1.json>

## API conventions

Follows Microsoft's [RESTful web API design best practices](https://learn.microsoft.com/en-us/azure/architecture/best-practices/api-design). Summary (details and the deliberate exceptions are in [`docs/ARCHITECTURE.md`](docs/ARCHITECTURE.md#rest-api-design-conventions)):

| Request | Success | Errors |
|---|---|---|
| `GET /api/v1/orders?limit=25&offset=0&status=Pending&minTotal=100&sort=-createdAt` | 200 `{ items, offset, limit, totalCount }` | 400 |
| `POST /api/v1/orders` | 201 + `Location` + body | 400, 415 |
| `GET /api/v1/orders/{id}` | 200 | 404 |
| `PUT /api/v1/orders/{id}` (full replace, idempotent) | 200 | 400, 404, 409 |
| `DELETE /api/v1/orders/{id}` | 204 | 404 |

All errors are `application/problem+json` and include `correlationId`. Every response carries a `Correlation-ID` header (send your own to trace a request end to end). Browsers can read `Location` and `Correlation-ID` (exposed via CORS).

## Authentication (Clerk)

The API accepts Clerk session tokens as `Authorization: Bearer <token>` and validates them with ASP.NET Core's JWT bearer handler, following [Clerk's manual verification guide](https://clerk.com/docs/guides/sessions/manual-jwt-verification). No Clerk SDK is needed.

| Check | How |
|---|---|
| Signature | RS256 only. Keys are fetched from `{Clerk:Issuer}/.well-known/openid-configuration` and refreshed automatically |
| Issuer | Must equal `Clerk:Issuer` (your Frontend API URL) |
| Lifetime | `exp`/`nbf` with 5 s clock skew (session tokens live about 60 s) |
| Authorized party | `azp` must be in `Clerk:AuthorizedParties` (skipped only if Clerk omitted `azp`) |
| Pending sessions | `sts=pending` is rejected (`Clerk:RejectPendingSessions`) |

All endpoints require a signed-in user by default. Health checks and the OpenAPI document opt out with `AllowAnonymous()`. Use cases read the caller through `ICurrentUser` (`UserId` = Clerk `sub`, `OrganizationId` = `o.id`). The sample `Orders` feature stores the creator and returns 404 for other users' orders.

Configure (the API refuses to start without it):

```json
"Clerk": {
  "Issuer": "https://<slug>.clerk.accounts.dev",
  "AuthorizedParties": [ "http://localhost:5173" ]
}
```

or `Clerk__Issuer` / `Clerk__AuthorizedParties__0` as environment variables. For local development, put your dev instance's values in user secrets: `dotnet user-secrets set "Clerk:Issuer" "https://<slug>.clerk.accounts.dev" --project src/Template.Api`.

Frontend (React): `const token = await getToken()` from `useAuth()`, then send `Authorization: Bearer ${token}`.

## API documentation (Swagger)

- The OpenAPI document is generated by the built-in `Microsoft.AspNetCore.OpenApi` package and rendered with Swagger UI (`Swashbuckle.AspNetCore.SwaggerUI`).
- Summaries come from `WithSummary`/`WithDescription`, response types from typed results (`Results<Ok<T>, ...>`), and property descriptions from XML doc comments (`<param>` on records).
- Enabled when `OpenApi:Enabled` is `true`: on in Development, off by default elsewhere. Turn on per environment with `OpenApi__Enabled=true`.
- Click **Authorize** and paste a Clerk session token (in the browser console of your signed-in frontend: `await window.Clerk.session.getToken()`). Tokens expire after about 60 s, so for longer manual testing create a JWT template with a longer lifetime in the Clerk Dashboard and use `getToken({ template: '<name>' })`.
- Generate a typed frontend client from `/openapi/v1.json`, e.g. with orval for TanStack Query hooks.

## Tests

```bash
dotnet test --solution Template.slnx
```

Uses Microsoft.Testing.Platform (configured in `global.json`). Integration tests start a `postgres:18` container, so Docker must be running. They sign Clerk-shaped tokens with a test RSA key, so no Clerk instance or network access is needed.

## Migrations

```bash
dotnet ef migrations add <Name> --project src/Template.Infrastructure --startup-project src/Template.Api --output-dir Persistence/Migrations
```

In production, migrations run as a one-off container (`--target migrator` image) before the API is restarted, using the schema-owner connection string. The API itself connects as `app_runtime`, which can read and write data but not change the schema.

## Docker images

```bash
docker build -f src/Template.Api/Dockerfile --target api      -t template-api .
docker build -f src/Template.Api/Dockerfile --target migrator -t template-migrator .
```

Runtime image: `aspnet:10.0-noble-chiseled` (no shell, non-root, port 8080). Health is checked from outside via `/health/live` and `/health/ready`.
