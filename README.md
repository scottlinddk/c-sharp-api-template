# c-sharp-api-template

.NET 10 Web API template, built to run in Docker on Hetzner Cloud.
Architecture and decisions: [`docs/ARCHITECTURE.md`](docs/ARCHITECTURE.md).

## What's inside

| Path | Purpose |
|---|---|
| `src/Template.Api` | HTTP edge: Minimal API endpoints, ProblemDetails, health checks, OpenAPI + Swagger UI, Dockerfile |
| `src/Template.Application` | Use cases (handlers, validators, `Result<T>`). No HTTP or Npgsql types |
| `src/Template.Domain` | Entities and invariants. No framework dependencies |
| `src/Template.Infrastructure` | EF Core + PostgreSQL, migrations, DI wiring |
| `tests/*` | Unit, architecture (layer rules) and integration tests (real Postgres via Testcontainers) |
| `deploy/compose` | Production Compose stack (Caddy, API, migrator, Postgres) + local override |

`Orders` is a sample feature showing the full path from endpoint to database. Replace it, and rename `Template` to your product name.

## Prerequisites

- .NET SDK 10.0.100+ (pinned in `global.json`)
- Docker (for integration tests and the Compose stack)

## Run locally

Option A: API on the host, Postgres in Docker

```bash
docker run -d --name template-pg -e POSTGRES_PASSWORD=postgres -e POSTGRES_DB=template -p 5432:5432 postgres:18
dotnet tool restore
dotnet ef database update --project src/Template.Infrastructure --startup-project src/Template.Api
dotnet run --project src/Template.Api
```

Option B: everything in Docker

```bash
cd deploy/compose
cp .env.example .env
docker compose up -d --build postgres api
docker compose run --rm --build migrate
```

Swagger UI: <http://localhost:5080/swagger> · OpenAPI document: <http://localhost:5080/openapi/v1.json>

## API documentation (Swagger)

- The OpenAPI document is generated by the built-in `Microsoft.AspNetCore.OpenApi` package and rendered with Swagger UI (`Swashbuckle.AspNetCore.SwaggerUI`).
- Summaries come from `WithSummary`/`WithDescription`, response types from typed results (`Results<Ok<T>, ...>`), and property descriptions from XML doc comments (`<param>` on records).
- Enabled when `OpenApi:Enabled` is `true`: on in Development, off by default elsewhere. Turn on per environment with `OpenApi__Enabled=true`.
- Generate a typed frontend client from `/openapi/v1.json`, e.g. with orval for TanStack Query hooks.

## Tests

```bash
dotnet test --solution Template.slnx
```

Uses Microsoft.Testing.Platform (configured in `global.json`). Integration tests start a `postgres:18` container, so Docker must be running.

## Migrations

```bash
dotnet ef migrations add <Name> --project src/Template.Infrastructure --startup-project src/Template.Api --output-dir Persistence/Migrations
```

In production, migrations run as a one-off container (`--target migrator` image) before the API is restarted, using the schema-owner connection string. The API itself connects as `app_runtime`, which can read and write data but not change the schema.

## Docker images

```bash
docker build -f src/Template.Api/Dockerfile --target api      -t template-api .
docker build -f src/Template.Api/Dockerfile --target migrator -t template-migrator .
```

Runtime image: `aspnet:10.0-noble-chiseled` (no shell, non-root, port 8080). Health is checked from outside via `/health/live` and `/health/ready`.
